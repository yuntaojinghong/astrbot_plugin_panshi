交给 AI 结构化解析
为什么需要闸门？「帮我」「麻烦」「怎么办」这类词在日常闲聊里出现频率极高， 如果命中就调用模型，等于把大量废话灌给 AI。闸门把「这句话值不值得模型介入」这件事 先用本地统计判断完 —— 关键洞察是：一句「收拾一下」值不值得响应， 取决于群里是否真的在出事，而这不需要问模型。
本地规则兜底
  • 标准句式（禁言张三 10分钟）本地直接执行，毫秒级、零 token
  • 完全没配模型时，常用指令照常可用，插件不会变成废物
  • 额度耗尽自动退回本地规则，不会瘫痪
意图缓存
  • 相同句子 120 秒内复用上次解析结果，不再重复问模型
  • 缓存按群隔离，不同群互不干扰
  • 开箱即用，无需任何配置
可调预算
  • intent_budget 每群每小时额度（默认 20 次）
  • intent_cooldown 两次调用最小间隔（默认 8 秒）
  • 设为 0 表示只用本地规则，完全不调用模型
intent-pipeline
消息进来
├─ 是 /指令  → 直接执行（零 token，毫秒级）
├─ @机器人 / 含动作词  → 直接交给 LLM（几乎不可能是闲聊）
└─ 其余消息 → 意图闸门（本地四道判定，零 token）
    ├─ ① 上下文佐证：近 3 分钟真有刷屏 / 广告 / 复读？
    ├─ ② 效果动词：是要求动作，还是单纯陈述？
    ├─ ③ 否定 / 闲聊：命中即否决
    └─ ④ 信用额度 + 冷却：还有预算吗？
       ├─ 未通过 → 静默放过（省下一次模型调用）
       └─ 通过 → 交给 LLM 解析意图
          ├─ 收集上下文（引用 / 最近发言 / @对象 / 群成员）
          ├─ 输出结构化 JSON
          ├─ 目标解析（名字模糊匹配 / 刷屏者推断）
          ├─ 权限校验
          └─ 高风险操作 → 确认后执行

四路目标定位

引用消息 > @某人 > QQ号 > 名字模糊匹配，自动选择最准确的一种。

  • 解析优先级：引用消息 > @某人 > 消息中的 QQ 号 > 名字模糊匹配
  • 遇到重名时结合最近发言与活跃度消歧
  • 「刚才刷屏的」「发广告的那个」结合最近消息缓存直接定位到人
  • 目标不存在或权限不足时明确提示原因，不静默失败
详细说明▼

上下文推断

结合最近发言记录，理解「刚才刷屏的」「发广告的那个」到底指谁。

  • 谁触发过刷屏检测、谁的消息被撤回过，都记录在案可推断
  • 最近发言条数、时间窗都参与判断（同一人 60 秒内 ≥5 条即视为高频）
  • 缓存定期自动清理，长期运行不膨胀
详细说明▼

高危确认

踢人、拉黑等不可逆操作先复述再执行，杜绝 AI 误判造成损失。

  • 踢人、拉黑等不可逆操作先复述「做什么 + 为什么」
  • 60 秒内回复「确认」才执行，「取消」或超时自动放弃
  • 杜绝 AI 误判误伤正常群友

// GET STARTED

三步装好

需要 AstrBot 4.24.2+ 与 NapCat（OneBot v11）协议端。4.24.2 以上才支持配置面板。

ZIP 下载压缩包最新版 · 直达 Release 页 TGZ 下载 tar.gz最新版 · 直达 Release 页 GIT 克隆仓库main 分支
1

获取插件

打开 Release 页下载压缩包，解压到 AstrBot 的插件目录；或直接克隆仓库。

cd AstrBot/data/plugins
git clone https://github.com/yuntaojinghong/astrbot_plugin_panshi.git
2

重启并在面板里配置

重启 AstrBot，进入插件详情页 → Pages → settings，打开图形配置面板。 面板会自动识别机器人所在的所有群，可按群独立设置规则；也可以直接在插件配置页调整八组配置项。

3

开始使用

发送 /群管帮助 查看完整指令，或直接对机器人说人话。

/禁言 @某人 10m    禁言十分钟
/踢 @某人 发广告    踢出并注明原因
/警告 @某人 刷屏    记一次违规
/净化 30             批量撤回最近30条
/签到                 每日签到得积分
